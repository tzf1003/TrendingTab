# 小组件恢复与界面重构实施计划

**目标：** 让已安装的 Developer ID 版本在桌面正常显示，完成三种组件尺寸、事件中心及设置界面的布局和交互重构。

**架构：** 主应用采集并发布 App Group 快照，小组件只读取有效快照。共享 App Intents 由应用和扩展共同发现，组件配置决定独立选择状态；新闻链接通过带条目身份的 URL 打开应用。

**技术：** macOS 14+、SwiftUI、WidgetKit、App Intents、Swift Package Manager、Developer ID。

## 布局

- 组件顶栏使用同一行：左箭头、榜单标签、右箭头；中、大号标签可直接点击，小号显示当前标签。标题字体为 14～16pt。
- 小号一列最多 5 行，中号两列各约 4 行，大号一列约 10 行。标题单行省略，行数根据可用空间计算，列表占满可用高度。
- 侧边距约 10pt；组件集中展示标题，更新时间在事件中心显示。
- 组件的默认榜单可在“编辑小组件”中选择；固定榜单适用于专用组件，可切换组件使用各自的配置槽。
- 等待数据、来源暂不可用和内容到期均展示可操作的状态；有效期结束后移除新闻。
- 事件中心提供热度排序、可切换的标签、明确的更新时间、新闻详情和原文入口。
- AI 分析位于独立的最右侧栏，支持逐字流式输出、连续追问、停止、重试，每条热点拥有临时独立会话。
- 设置使用左侧分类导航和右侧内容，保持所有现有配置入口、AI 凭据与更新操作。

## 实现与验证

1. 签名身份：用实际 v0.2.12 包重现缺失 Team ID / App ID；重签名保留 Xcode 的最终权限，并在 CI 检查身份与 profile 匹配。
2. 小组件：共享 Intent 类型、精简扩展依赖、明确 placeholder 和数据失效状态，重构三种尺寸布局和独立选择键。
3. 交互：新闻 URL 精确携带条目、事件及标签，应用冷启动和重复点击都能定位对应新闻；采集完成后请求 WidgetKit 刷新。
4. 主应用界面：重构主题、事件中心、设置及菜单栏，复用现有业务模型。
5. 回归：Swift 测试验证快照过期、配置隔离、删除后的回退、精确链接；真实签名包验证 Team ID、App ID、profile、扩展点和通用架构。
6. 验收：本机安装后观察桌面三种尺寸，点击标签和新闻；CI 发布签名公证 DMG 后再次下载回读。

## 风险检查

- 旧组件已有配置的解码与默认值兼容。
- 同榜单多个组件的状态隔离，以及编辑配置后的回退。
- 采集暂停、应用退出或断网后快照到期。
- 应用未启动时点新闻、同条新闻反复点击、目标已掉榜。
- 公证通过与 WidgetKit 真正生成时间线分别验收。
